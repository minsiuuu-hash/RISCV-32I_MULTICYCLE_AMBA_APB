# RISC-V RV32I Multi-Cycle CPU with AMBA APB

This project extends the RISC-V RV32I Multi-Cycle CPU by adding an AMBA APB bus structure.

The original Multi-Cycle CPU directly accessed data memory.  
In this project, the memory access path was changed to an APB-based bus structure, so the processor can access RAM and peripherals through load/store instructions.

## AMBA APB Bus

APB is a simple bus protocol used for low-speed peripheral register access.

### 1. Simple Bus Structure

APB does not support complex burst transfers or pipelined transfers.  
It performs one read or write transfer at a time.

### 2. Bus for Register Access

APB is mainly used to access peripheral registers, such as control registers and status registers.  
The processor can read from or write to these registers through the APB bus.

### 3. Slave-Ready Based Handshake

APB uses a handshake mechanism based on the `PREADY` signal.  
When the slave peripheral is ready, it asserts `PREADY`, and the master completes the transfer after checking this signal.

## Difference from the Original Multi-Cycle CPU

The original Multi-Cycle CPU accessed data memory directly through memory signals such as address, write data, read data, and write enable.

In this APB version, the memory access path was changed to a bus-based structure.  
The RISC-V CPU does not directly access RAM or peripherals. Instead, load/store instructions generate bus read/write requests, and the APB master converts these requests into APB transfers.

| Part | Original Multi-Cycle CPU | Multi-Cycle CPU with APB |
|---|---|---|
| Memory Access | Direct data memory access | Bus-based access through APB master |
| Load Instruction | Reads data directly from data memory | Sends read request and waits for `bus_ready` |
| Store Instruction | Writes data directly to data memory | Sends write request through APB transfer |
| Address Handling | Data memory address only | Address decoder selects RAM or peripheral |
| I/O Control | Not memory-mapped | GPO, GPI, GPIO, FND, UART are controlled by memory-mapped I/O |

## APB Integration

The CPU load/store interface was modified for APB communication.

| CPU Bus Signal | Description |
|---|---|
| `bus_addr` | Address generated by the CPU for load/store access |
| `bus_wdata` | Write data sent from the CPU |
| `bus_rdata` | Read data returned from RAM or peripheral |
| `bus_wreq` | Write request generated by store instructions |
| `bus_rreq` | Read request generated by load instructions |
| `bus_ready` | Ready signal returned from the APB master/peripheral |

The APB master receives the CPU bus request and performs an APB transfer using APB signals.

| APB Signal | Description |
|---|---|
| `PADDR` | APB address |
| `PWDATA` | Write data |
| `PRDATA` | Read data |
| `PWRITE` | Write control signal |
| `PSEL` | Slave select signal |
| `PENABLE` | Transfer enable signal |
| `PREADY` | Slave ready signal |

```text
CPU Load/Store
      ↓
CPU Bus Interface
      ↓
APB Master
      ↓
Address Decoder
      ↓
RAM / GPO / GPI / GPIO / FND / UART
```

## APB Transfer Flow

The APB master is implemented with three main states.

| State | Description |
|---|---|
| `IDLE` | Waits for a read or write request from the CPU |
| `SETUP` | Selects the target slave using `PSEL` and prepares address/data/control signals |
| `ACCESS` | Enables the APB transfer using `PENABLE` and waits for `PREADY` |

The transfer is completed when the selected slave asserts `PREADY`.

## Memory-Mapped I/O

In this project, ROM, RAM, and APB peripherals were assigned to specific address ranges using a memory map.

The RISC-V processor accesses each device through load/store instructions, and the address decoder selects the corresponding memory or peripheral based on the accessed address.

GPO, GPI, GPIO, FND, and UART were mapped as APB peripherals, enabling the processor to control external I/O, display output, and serial communication through memory-mapped I/O.

## Memory Map

| Address Range | Size | Region | Description |
|---|---:|---|---|
| `0x0000_0000 ~ 0x0000_0FFF` | 4 KB | ROM | Instruction Memory |
| `0x0000_1000 ~ 0x0000_1FFF` | 4 KB | Reserved | Not Used |
| `0x1000_0000 ~ 0x1000_0FFF` | 4 KB | RAM | Data Memory |
| `0x1000_1000 ~ 0x1000_1FFF` | 4 KB | Reserved | Not Used |
| `0x2000_0000 ~ 0x2000_0FFF` | 4 KB | GPO | Output Peripheral |
| `0x2000_1000 ~ 0x2000_1FFF` | 4 KB | GPI | Input Peripheral |
| `0x2000_2000 ~ 0x2000_2FFF` | 4 KB | GPIO | General Purpose I/O |
| `0x2000_3000 ~ 0x2000_3FFF` | 4 KB | FND | 7-Segment Display |
| `0x2000_4000 ~ 0x2000_4FFF` | 4 KB | UART | Serial Communication |
| `0x2000_5000 ~ 0x2000_5FFF` | 4 KB | Reserved | APB Extension Area |

## Peripherals

| Peripheral | Description |
|---|---|
| GPO | General Purpose Output peripheral |
| GPI | General Purpose Input peripheral |
| GPIO | Bidirectional General Purpose I/O peripheral |
| FND | 7-segment display output peripheral |
| UART | Serial communication peripheral |

## Key Points

- The RISC-V CPU core was extended from direct memory access to bus-based memory access.
- Load/store instructions are used to access both RAM and memory-mapped peripherals.
- The APB master handles address decoding, slave selection, and `PREADY`-based handshake.
- GPO, GPI, GPIO, FND, and UART were connected as memory-mapped APB peripherals.
